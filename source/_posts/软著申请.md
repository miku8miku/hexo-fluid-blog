<a href="https://www.ccopyright.com.cn/" rel="noopener nofollow ugc" target="_blank">中国版权保护中心</a></p><blockquote class="reader-callout callout-tip"><div class="callout-header"><span class="callout-icon">💡</span><span class="callout-title">一些 Q &amp;amp; A</span></div><div class="callout-body"><p>
<strong>关于AI的使用?</strong><br/>
根据各位佬友描述的最新情况，最近下证似乎对 AIGC 内容的审查更加严格，请看这位佬的遭遇<br/>
<a class="inline-onebox" href="https://linux.do/t/topic/2756623/74" rel="noopener nofollow ugc" target="_blank">全网最详细的软著（软件著作权）申请指北 - #74，来自 ACTIONAI</a><br/>
目前我的观点是代码可以使用 AI 编写，但是文档鉴别材料请按照本文所述方法手动编写，这位佬就是因为文档鉴别材料被认为 AIGC 才被要求补充材料</p>

<p>软著要花钱吗？<br/>
答：不用，个人申请（就是你自己完成流程），不花钱。找代理机构帮你整理文档，做项目等收费那就是他们的事了，跟软著无关，属于技术服务。现在软著证书的申请完全是电子化的，不涉及邮寄等，最后给出的证书也是电子证书</p>
<p>申请软著有啥价值？<br/>
答：我认为没价值，没含金量。不过是学校加加分，单位发点钱的 “含金量” 证明罢了。</p>
<p>开源项目能申请软著吗？<br/>
答：不确定，但应该可以，别提到就行。我的一个项目就是在 GitHub 上开源的，也没有提交相关的证明（我觉得这种根本就无法证明）。所以有需要的就尝试直接申请，也选择<strong>未发表</strong>。</p>
<p>软著对项目的要求高吗？<br/>
答：对内容本身几乎无要求，主要是只提交程序鉴别文件还是不完整的，可能最多就是查个重，至于有没有 Bug，功能做的怎么样就没人管你了，只要能有个 Demo 在写文档的时候截图就行了（<span class="spoiler">不行就 F12 改一改呗 <img alt=":joy:" class="emoji" height="20" loading="lazy" src="https://cdn.ldstatic.com/images/emoji/twemoji/joy.png?v=15" title=":joy:" width="20"/></span>）</p>
</div></blockquote><blockquote class="reader-callout callout-tip"><div class="callout-header"><span class="callout-icon">💡</span><span class="callout-title">提示</span></div><div class="callout-body"><p>
在一切开始之前，需要先在软件著作权的官网上进行<strong>注册和实名认证</strong>，注意此步骤可能需要三天，建议在开始申请前提前进行</p>

</div></blockquote><p>整个软著申请的时间漫长，需要的文件资料繁琐，尤其是以学校或单位身份申请时更是非常麻烦，但相较于专利等其他证明，<strong>软著本身对项目代码的要求不高，也无需提供完整项目成品或Demo，只需要提交PDF文件证明代码即可（所以应该不会对代码有较多审查）</strong>。适合没有开发和项目经验的佬友借助 AI 的力量来拿证，整体对小白很友好。</p><blockquote class="reader-callout callout-tip"><div class="callout-header"><span class="callout-icon">💡</span><span class="callout-title">提示</span></div><div class="callout-body"><p>
算上学校或单位层层审批，到软著中心方面的几个月的审核，整个流程走下来可能需要 4 到 5 个月，所以时间比较紧的佬友要注意提前申请，避免影响使用这有 “含金量” 的证书</p>

</div></blockquote><h2 id="step-1--开发一个-项目"><a aria-label="标题链接" class="anchor" href="#step-1--开发一个-项目" name="p-21600104-step-1-2"></a>Step 1 . 开发一个 “项目”</h2><p>如题，申请软著肯定是需要软件的，建议将软件的名称命名为 “xxxx 软件” 或 “xxxx 系统”，实在不行就问一下 AI，让它看一下项目再告诉你比较好的命名。</p><p>建议项目代码量在 10000 行以上，因为后面需要生成 “程序鉴别材料”，就是要将源代码输出到共 60 张 A4 纸上，每页显示不少于 50 行（具体要求后面细说）</p><p>项目本身可以没有完整成品，因为申请软著没有人管项目是否能正常使用，他们只会看你上传的文档，不过 Demo 最好有一个，便于在写文档的时候照着截图</p><blockquote class="reader-callout callout-tip"><div class="callout-header"><span class="callout-icon">💡</span><span class="callout-title">提示</span></div><div class="callout-body"><p>
申请软著，项目本身可以非常简单，只需要有一定的功能可以写出文档，代码量到 10000 左右（AI 写非常快，其实很容易超过），所以做出一个可以申请的项目本身不是难事</p>

<p>对项目没有思路的解决办法：</p>
<ol>
<li>在 GitHub 上找一找简单的项目，然后寻找思路，再构建自己的软件，你可以在设计思路上和他人相同，但界面和代码的相似度别太高，否则<strong>可能</strong>会被认定为非原创；</li>
<li>从自身的痛点出发，可以想想平常生活中有没有什么实际的需求，从小的需求点出发，让 AI 指导你去构建属于你的软件/网站/…… 这里用各种 Vibe Coding 功能就会非常方便</li>
<li>从你的作业出发，随意打开 C++ 或者 Python 的书，翻一翻课后作业或者例题，总能找到一些有点意思有点小用的出发点，再引发你的思考去实现或让 AI 实现</li>
<li>从 B 站/抖音….. 出发，找一些大家做的比较好玩的项目，比如最近挺火的合乎周礼翻译器，就可以考虑将其思路进行移植，开发一种 “基于人工智能的古文转化系统”？ <img alt=":joy:" class="emoji" height="20" loading="lazy" src="https://cdn.ldstatic.com/images/emoji/twemoji/joy.png?v=15" title=":joy:" width="20"/>这只是一个思路</li>
<li>实在不行，搜索编程相关内容，里面就有一堆项目实战，不过看一看找找思路就得了，充钱上课就真成韭菜了</li>
</ol>
</div></blockquote><p>接下来就是根据 Vibe Coding 或者直接自己动手开发准备项目了，这一步花费的时间因人而异，但还是不建议花费较多的时间去优化或者修改 Bug，没必要，他们并不会审核实际的功能，只需要<strong>你的文档里面展示出来了、写的有道理就行了</strong></p><p>请确保到这里，你的项目能正常工作，有点测试数据让里面至少有内容，然后能截图展示并描述相关功能，就可以考虑进入下一步了</p><h2 id="step-2--准备相关文件"><a aria-label="标题链接" class="anchor" href="#step-2--准备相关文件" name="p-21600104-step-2-3"></a>Step 2 . 准备相关文件</h2><p>总的来说，整个软件著作权的申请需要这些文件，后面分文件细讲，这里简单提一下：</p><ol>
<li>程序鉴别材料：将具体的代码变成 PDF 文件，就是生成一个文档，总共 60 页，每一页都写上代码</li>
